# وثيقة المتطلبات

## 1. نظرة عامة على التطبيق

### 1.1 اسم التطبيق
Vodafone Fakka Premium

### 1.2 المالك
Nader Akram

### 1.3 الإصدار
v3.0.38

### 1.4 الوصف
منصة ويب احترافية لشحن كروت الفكة مع نظام اشتراكات وأكواد ترخيص، مصممة بواجهة عربية فاخرة وتدعم التكامل المستقبلي مع محرك شحن خارجي. تتضمن مركز شبكات متعدد لعرض خدمات Vodafone وOrange وEtisalat وWE، مع نظام إدارة كروت ديناميكي كامل وتحسينات أداء شاملة. تشمل المرحلة الجديدة إعادة بناء لوحة الإدارة بالكامل بصفحات كاملة احترافية، بالإضافة إلى نظام تقييم الكروت واقتراح التعديلات، ونظام وضع المعاينة Preview Mode، وإعادة بناء قسم عروض واشتراكات فودافون بالكامل.

### 1.5 المبادئ الأساسية
- جميع البيانات ديناميكية (الكروت، الأسعار، الوحدات، الحالات)
- لا توجد بيانات ثابتة أو افتراضية
- النظام جاهز للربط مع API خارجي أو Recharge Engine
- تصميم Premium حديث بنمط Dark Luxury UI
- دعم كامل للغة العربية RTL
- Mobile First و Responsive
- Offline-First مع مزامنة ذكية
- منع التكرار في جميع العمليات
- لوحة إدارة احترافية بصفحات كاملة بدون Popup/Modal
- حماية Server-Side لجميع الصلاحيات والاشتراكات
- عدم تخزين passwords أو OTP أو tokens في logs أو frontend

### 1.6 الألوان

- Accent: #FF3B3B

- Borders: rgba(255,255,255,0.08)

## 2. المستخدمون وسيناريوهات الاستخدام

### 2.1 المستخدمون المستهدفون
- المستخدمون النهائيون: أفراد يحتاجون لشحن كروت الفكة واستعراض خدمات الشبكات والاشتراك في عروض فودافون
- مستخدمو المعاينة Preview Users: أفراد يريدون تجربة التطبيق قبل الاشتراك
- المسؤولون (Admin): إدارة المستخدمين والاشتراكات والأكواد والكروت والإصدارات والميزات ووضع المعاينة
- المسؤولون الرئيسيون (Super Admin): صلاحيات كاملة على النظام

### 2.2 السيناريوهات الأساسية
- تفعيل الاشتراك باستخدام كود تفعيل
- الدخول إلى وضع المعاينة Preview Mode لتجربة التطبيق
- شحن كروت الفكة بشكل متكرر
- استعراض خدمات الشبكات المختلفة
- استعراض عروض فودافون والاشتراك فيها
- إدارة الاشتراكات القادمة
- شحن الرصيد من قسم عروض فودافون
- حفظ الأرقام المفضلة للشحن السريع
- مراجعة سجل العمليات السابقة
- مراجعة الإحصائيات التفصيلية
- تقييم الكروت واقتراح تعديلات على بياناتها
- إدارة الاشتراكات والأكواد والكروت (للمسؤولين)
- إدارة الأصول المرئية الديناميكية (للمسؤولين)
- حذف المستخدمين نهائياً (للمسؤولين)
- مراقبة المستخدمين والإصدارات في الوقت الفعلي (للمسؤولين)
- إدارة الميزات والإصدارات بدون تحديث APK (للمسؤولين)
- تنفيذ إجراءات متقدمة على حسابات المستخدمين (للمسؤولين)
- مراجعة تقييمات واقتراحات المستخدمين على الكروت (للمسؤولين)
- إدارة وضع المعاينة Preview Mode (للمسؤولين)

### 3.2 شاشة البداية (Splash Screen)

#### الوظيفة
- عرض شعار فاخر للتطبيق (ديناميكي قابل للتعديل من لوحة الأدمن)
- عرض النصوص: Vodafone Fakka Premium / Powered By / Nader Akram
- تشغيل Animation احترافي أثناء التحميل
- تحميل البيانات الأساسية من التخزين المحلي أولاً
- الانتقال التلقائي للصفحة التالية بعد اكتمال التحميل

### 3.3 نظام التفعيل

#### الوظيفة
- يظهر عند أول دخول للمستخدم أو عند انتهاء الاشتراك
- عرض كارت فاخر بعنوان: تفعيل الاشتراك
- وصف: أدخل كود التفعيل الخاص باشتراكك لتفعيل الحساب
- حقل إدخال: كود التفعيل
- زر: تفعيل الاشتراك
- زر واتساب مباشر لرقم: 01222692182
- رسالة واتساب تلقائية: السلام عليكم أرغب في تفعيل اشتراك Vodafone Fakka Premium برجاء إرسال تفاصيل الدفع.
- زر معاينة التطبيق: يظهر إذا كان Preview Mode مفعلاً من لوحة الأدمن
- بعد التفعيل الناجح: عرض حالة الاشتراك، تاريخ التفعيل، تاريخ الانتهاء، الأيام المتبقية
- جميع البيانات ديناميكية من الخادم

### 3.4 الصفحة الرئيسية

#### الوظيفة
- عرض شعار الهيدر في أعلى اليمين (ديناميكي)
- عرض Badge معاينة في أعلى الشاشة (إذا كان المستخدم في Preview Mode)
- عرض كارت ترحيب فاخر يحتوي على: أيقونة الترحيب (ديناميكية)، اسم المستخدم، حالة الاشتراك، تاريخ التفعيل، تاريخ الانتهاء، الأيام المتبقية، إجمالي العمليات، إجمالي الكروت، إجمالي المبالغ، آخر عملية

- روابط سريعة للوظائف الرئيسية
- إخفاء جميع أدوات المطورين والتصحيح من واجهة المستخدم العادي
- تحميل البيانات من التخزين المحلي أولاً ثم المزامنة

### 3.5 صفحة الشبكات

- تحميل الشعارات من التخزين المحلي

### 3.7 قسم عروض واشتراكات فودافون (PHASE 1)

#### 3.7.1 الصفحة الرئيسية للقسم

##### الوظيفة
- عرض 5 اختصارات/أقسام واضحة ومضغوطة ومتجاوبة مع شاشة الهاتف
- كل اختصار عبارة عن كارت مضغوط يحتوي على: أيقونة، عنوان، وصف مختصر
- الأقسام الخمسة:
  1. عروض فليكس
  2. عروض الإنترنت
  3. عروض أخرى
  4. الاشتراكات القادمة
  5. شحن الرصيد
- التصميم: Dark/RTL/Premium، Mobile First، بدون Horizontal Overflow
- عند الضغط على أي اختصار: الانتقال إلى صفحة القسم المحدد داخل نفس التطبيق
- بدون Redirect إلى Home
- بدون Sidebar عالق
- بدون صفحة خارجية
- استخدام نفس Header و Bottom Navigation الموجودين

#### 3.7.2 صفحة عروض فليكس

##### الوظيفة
- صفحة مستقلة داخل التطبيق
- Header: عنوان عروض فليكس، زر العودة
- عرض جميع عروض فليكس القادمة من نظام العروض
- كل عرض في Card مضغوط مناسب للموبايل يحتوي على:
  - اسم العرض
  - التفاصيل/الوصف
  - السعر
  - Offer ID (داخلياً، غير ظاهر للمستخدم)
  - زر اشتراك
- عند الضغط على العرض: فتح تفاصيله بوضوح في نفس الصفحة أو صفحة فرعية
- عند الضغط على زر اشتراك: تجهيز Action Hook (لا تنفيذ فعلي في PHASE 1)
- التصميم: Cards مضغوطة، بدون تداخل، Mobile First
- Loading State أثناء تحميل العروض
- رسالة لا توجد عروض متاحة حالياً إذا كانت القائمة فارغة

#### 3.7.3 صفحة عروض الإنترنت

##### الوظيفة
- نفس نظام صفحة عروض فليكس
- عرض عروض الإنترنت فقط
- نفس هيكل Card والتفاصيل
- نفس Action Hook للاشتراك (لا تنفيذ فعلي في PHASE 1)

#### 3.7.4 صفحة عروض أخرى

##### الوظيفة
- نفس نظام صفحة عروض فليكس
- عرض العروض التي لا تنتمي إلى فليكس أو الإنترنت
- نفس هيكل Card والتفاصيل
- نفس Action Hook للاشتراك (لا تنفيذ فعلي في PHASE 1)

#### 3.7.5 صفحة الاشتراكات القادمة

##### الوظيفة
- صفحة مستقلة داخل التطبيق
- Header: عنوان الاشتراكات القادمة، زر العودة
- عرض الاشتراكات القادمة للمستخدم
- كل اشتراك في Card مضغوط يحتوي على:
  - اسم/وصف الباقة
  - الحالة (نشط، معلق، قادم)
  - السعر
  - زر إلغاء الاشتراك
  - زر شحن الباقة
  - المبلغ الإجمالي (عند الحاجة)
- عند الضغط على زر إلغاء الاشتراك: تجهيز Action Hook (لا تنفيذ فعلي في PHASE 1)
- عند الضغط على زر شحن الباقة: تجهيز Action Hook (لا تنفيذ فعلي في PHASE 1)
- التصميم: Cards مضغوطة، بدون تداخل، Mobile First
- Loading State أثناء تحميل الاشتراكات
- رسالة لا توجد اشتراكات قادمة حالياً إذا كانت القائمة فارغة

#### 3.7.6 صفحة شحن الرصيد

##### الوظيفة
- اختصار/واجهة صغيرة مرتبطة مباشرة بنظام شحن الرصيد الموجود أصلاً في التطبيق
- لا إنشاء نظام شحن جديد
- لا تكرار منطق الشحن
- لا إنشاء نسخة ثانية من نظام الشحن
- الاختصار داخل هذا القسم فقط ويستدعي نفس نظام الشحن الأساسي
- الحفاظ على نظام فحص شبكة Vodafone Cash / Bridge الموجود في نظام الشحن الأصلي
- عرض واجهة مبسطة تحتوي على:
  - حقل إدخال رقم الهاتف
  - حقل إدخال الرقم السري
  - اختيار الكارت
  - زر شحن
- عند الضغط على زر شحن: استدعاء نظام الشحن الأساسي الموجود
- التصميم: مضغوط، Mobile First، متناسق مع باقي القسم

## 4. القواعد والمنطق

### 4.1 نظام الصلاحيات
- User: صلاحيات المستخدم العادي (الشبكات، المفضلة، السجل، الإحصائيات، الإعدادات)
- Preview User: صلاحيات محدودة (تصفح الأقسام المتاحة للمعاينة فقط، لا يحصل على أي صلاحيات مدفوعة)
- Admin: صلاحيات إدارية (إدارة المستخدمين، الاشتراكات، الأكواد، الكروت، العمليات، الأصول المرئية، الإصدارات، الميزات، المراقبة، تقييمات الكروت، Preview Mode)
- Super Admin: صلاحيات كاملة على جميع أقسام النظام

### 4.2 منطق التفعيل
- عند إدخال كود تفعيل صحيح: تفعيل الاشتراك، تسجيل تاريخ التفعيل، حساب تاريخ الانتهاء بناءً على مدة الكود، ربط الكود بالمستخدم، تحديث حالة الكود إلى مستخدم، تحديث access_mode إلى subscribed
- عند إدخال كود خاطئ أو مستخدم مسبقاً: عرض رسالة خطأ، عدم السماح بالمتابعة

### 4.3 منطق Preview Mode

#### 4.3.1 الدخول إلى Preview Mode
- عند الضغط على زر معاينة التطبيق في شاشة التفعيل:
  - إنشاء حساب مؤقت للمستخدم (إذا لم يكن موجوداً)
  - تحديث access_mode إلى preview
  - تحديث subscription_status إلى none
  - عدم إضافة أيام اشتراك
  - عدم إنشاء اشتراك وهمي
  - عدم إضافة رصيد
  - عدم تغيير حالة الاشتراك للمشتركين
  - الانتقال إلى الصفحة الرئيسية

#### 4.3.2 Access Model
- subscription_status: active، expired، none
- access_mode: subscribed، preview
- كل مستخدم له subscription_status و access_mode

#### 4.3.3 حماية Server-Side
- كل API مدفوع يتحقق من:
  - subscription_status: يجب أن يكون active
  - access_mode: يجب أن يكون subscribed
- إذا كان access_mode = preview:
  - رفض الطلب
  - إرجاع حالة SUBSCRIPTION_REQUIRED
  - عرض رسالة احترافية: هذه الميزة تتطلب اشتراكاً نشطاً

#### 4.3.4 واجهة Preview
- عرض Badge معاينة في أعلى الشاشة بوضوح
- عند محاولة فتح قسم مدفوع:
  - عرض رسالة احترافية: هذه الميزة تتطلب اشتراكاً نشطاً
  - عرض زر تفعيل الاشتراك
- الأقسام المتاحة للمعاينة:
  - يتم تحديدها من لوحة الأدمن
  - يتم تحميلها ديناميكياً من الخادم
  - يتم تطبيقها فوراً بدون تحديث APK

#### 4.3.5 Admin Control
- تشغيل/إيقاف Preview Mode:
  - تشغيل: يظهر زر معاينة التطبيق في شاشة التفعيل
  - إيقاف: يختفي الزر من شاشة التفعيل
- إظهار/إخفاء زر معاينة التطبيق
- تحديد الأقسام المتاحة للمعاينة:
  - متاح للمعاينة: يمكن للمستخدم الوصول إليه
  - يتطلب اشتراك: يتم رفض الوصول مع رسالة احترافية
  - متوقف: يتم رفض الوصول مع رسالة القسم متوقف مؤقتاً
  - صيانة: يتم رفض الوصول مع رسالة مخصصة من Admin
- عرض إحصائيات Preview Mode
- سجل دخول المستخدمين إلى Preview Mode

#### 4.3.6 التحويل من Preview إلى Subscribed
- عند تفعيل الاشتراك:
  - تحديث access_mode إلى subscribed
  - تحديث subscription_status إلى active
  - تسجيل تاريخ التفعيل
  - حساب تاريخ الانتهاء
  - ربط الكود بالمستخدم
  - تحديث حالة الكود إلى مستخدم

### 4.4 منطق الشحن
- التحقق من صلاحية الاشتراك قبل السماح بالشحن
- التحقق من access_mode: يجب أن يكون subscribed
- التحقق من subscription_status: يجب أن يكون active
- إذا كان access_mode = preview: رفض الطلب، عرض رسالة هذه الميزة تتطلب اشتراكاً نشطاً
- التحقق من صحة رقم الهاتف والرقم السري
- التحقق من اختيار الكارت
- التحقق من حالة الكارت من product_config
- إذا كان الكارت (maintenance/development/unavailable): لا يُرسل أي API، يظهر Dialog: تم إيقاف هذا المنتج مؤقتاً، وسيعود للعمل فور توفره.
- إذا كان disabled_execution: الكارت ظاهر لكن التنفيذ معطّل بنفس الـ Dialog
- عرض رسالة تنبيه قبل التنفيذ: يرجى التأكد قبل التنفيذ من عدم وجود أي مبلغ مستحق أو استلاف أو نوتة على الخط المرسل إليه، لأن ذلك قد يؤدي إلى عدم إتمام العملية بنجاح.
- منع إرسال الطلب مرتين (Request Deduplication)
- إرسال طلب الشحن (سيتم ربطه لاحقاً مع Recharge Engine)
- انتظار النتيجة النهائية قبل عرض الرسالة
- تسجيل العملية في السجل
- عرض نتيجة العملية (نجاح أو فشل)
- إذا نجحت العملية: لا تظهر رسالة فشل أبداً، عرض زر تقييم الكارت (إذا كانت الميزة مفعلة)
- نظام الشحن الحالي يعمل بشكل صحيح ولا يجب تعديله

### 4.5 منطق الاشتراكات
- حساب الأيام المتبقية تلقائياً
- عند انتهاء الاشتراك: تحديث حالة الاشتراك إلى منتهي، منع المستخدم من الشحن، عرض شاشة التفعيل، إرسال إشعار تجديد

### 4.6 منطق الأكواد
- كل كود يستخدم مرة واحدة فقط
- الكود المعطل لا يمكن استخدامه
- الكود المحذوف لا يظهر في النظام

### 4.7 منطق البيانات الديناميكية
- جميع الكروت يتم تحميلها من product_config في Supabase
- جميع إعدادات الكروت ديناميكية
- لا توجد بيانات ثابتة في الكود
- النظام يعرض فقط ما يتم تحميله
- في حالة عدم توفر بيانات: عرض رسالة لا توجد كروت متاحة حالياً

### 4.8 منطق الإحصائيات
- حساب جميع الإحصائيات ديناميكياً من قاعدة البيانات
- تحديث الإحصائيات تلقائياً عند إضافة عملية جديدة
- عرض Charts ديناميكية بناءً على البيانات الفعلية

### 4.9 منطق إخفاء أدوات المطورين
- إخفاء جميع أدوات المطورين من واجهة المستخدم العادي
- لا يتم حذف الكود أو إزالة الوظائف
- يتم إخفاء العناصر من واجهة المستخدم فقط
- تستمر جميع الوظائف في العمل داخلياً
- المسؤولون (Admin/Super Admin) يمكنهم الوصول لهذه الأدوات عند الحاجة

### 4.10 منطق الأصول المرئية الديناميكية
- مواقع الأصول المرئية: شعار الهيدر في أعلى اليمين، أيقونة كارت الترحيب، شعار شاشة البداية، شعارات الشبكات في صفحة الشبكات وصفحات الشبكات الفردية
- عملية التحديث: Admin يرفع صورة جديدة، رفع الملف إلى Supabase Storage، تحديث قاعدة البيانات بالرابط الجديد، تحديث فوري لجميع المستخدمين، لا حاجة لتحديث APK
- التحقق من الصيغة والحجم: التحقق من صيغة الملف (PNG, JPG, JPEG, WEBP, SVG)، التحقق من حجم الملف (أقل من 10 MB)، رفض الملفات غير المطابقة

### 4.11 منطق صفحة الشبكات
- عرض 4 بطاقات للشبكات بتصميم Premium
- كل بطاقة تعرض شعار الشبكة الديناميكي من Asset Management
- تطبيق لون الشبكة الرسمي في التصميم
- عرض عدد الخدمات (حالياً 0 لجميع الشبكات)
- عند الضغط على أي بطاقة: الانتقال إلى صفحة الشبكة المحددة
- Animations ناعمة بدون تهنيج
- بدون إعادة تحميل الصفحة

### 4.12 منطق صفحات الشبكات الفردية
- البنية الحالية: عرض Header بشعار الشبكة واسمها ووصف احترافي، عرض قسم الخدمات برسالة تحت التطوير، زر العودة للشبكات
- البنية المستقبلية (Modular): جاهزة لإضافة أقسام (فكة، دقائق، ميجابايت، باقات، كروت، عروض، خدمات)

### 4.13 منطق قسم عروض واشتراكات فودافون (PHASE 1)

#### 4.13.1 منطق الصفحة الرئيسية للقسم
- عرض 5 اختصارات/أقسام في Cards مضغوطة
- كل Card يحتوي على: أيقونة، عنوان، وصف مختصر
- عند الضغط على أي Card: الانتقال إلى صفحة القسم المحدد داخل نفس التطبيق
- بدون Redirect إلى Home
- بدون Sidebar عالق
- بدون صفحة خارجية
- استخدام نفس Header و Bottom Navigation الموجودين
- Animations ناعمة عند التنقل

#### 4.13.2 منطق صفحة عروض فليكس
- تحميل جميع عروض فليكس من نظام العروض
- عرض كل عرض في Card مضغوط
- Card يحتوي على: اسم العرض، التفاصيل/الوصف، السعر، زر اشتراك
- Offer ID يُخزن داخلياً ولا يظهر للمستخدم
- عند الضغط على العرض: فتح تفاصيله بوضوح
- عند الضغط على زر اشتراك: تجهيز Action Hook (لا تنفيذ فعلي في PHASE 1)
- Loading State أثناء تحميل العروض
- رسالة لا توجد عروض متاحة حالياً إذا كانت القائمة فارغة
- Mobile First، بدون Horizontal Overflow

#### 4.13.3 منطق صفحة عروض الإنترنت
- نفس منطق صفحة عروض فليكس
- تحميل عروض الإنترنت فقط
- نفس هيكل Card والتفاصيل
- نفس Action Hook للاشتراك (لا تنفيذ فعلي في PHASE 1)

#### 4.13.4 منطق صفحة عروض أخرى
- نفس منطق صفحة عروض فليكس
- تحميل العروض التي لا تنتمي إلى فليكس أو الإنترنت
- نفس هيكل Card والتفاصيل
- نفس Action Hook للاشتراك (لا تنفيذ فعلي في PHASE 1)

#### 4.13.5 منطق صفحة الاشتراكات القادمة
- تحميل الاشتراكات القادمة للمستخدم
- عرض كل اشتراك في Card مضغوط
- Card يحتوي على: اسم/وصف الباقة، الحالة، السعر، زر إلغاء الاشتراك، زر شحن الباقة، المبلغ الإجمالي (عند الحاجة)
- عند الضغط على زر إلغاء الاشتراك: تجهيز Action Hook (لا تنفيذ فعلي في PHASE 1)
- عند الضغط على زر شحن الباقة: تجهيز Action Hook (لا تنفيذ فعلي في PHASE 1)
- Loading State أثناء تحميل الاشتراكات
- رسالة لا توجد اشتراكات قادمة حالياً إذا كانت القائمة فارغة
- Mobile First، بدون Horizontal Overflow

#### 4.13.6 منطق صفحة شحن الرصيد
- لا إنشاء نظام شحن جديد
- لا تكرار منطق الشحن
- لا إنشاء نسخة ثانية من نظام الشحن
- استخدام اختصار/واجهة صغيرة مرتبطة مباشرة بنظام شحن الرصيد الموجود أصلاً في التطبيق
- الاختصار داخل هذا القسم فقط ويستدعي نفس نظام الشحن الأساسي
- الحفاظ على نظام فحص شبكة Vodafone Cash / Bridge الموجود في نظام الشحن الأصلي
- عرض واجهة مبسطة تحتوي على: حقل إدخال رقم الهاتف، حقل إدخال الرقم السري، اختيار الكارت، زر شحن
- عند الضغط على زر شحن: استدعاء نظام الشحن الأساسي الموجود
- التصميم: مضغوط، Mobile First، متناسق مع باقي القسم

#### 4.13.7 قواعد PHASE 1
- لا ربط API أو عمليات الاشتراك/الإلغاء الفعلية في هذه المرحلة
- لا تعديل السكريبت المرفق (vodafone_offers_subscriptions.py)
- لا إنشاء API جديد إذا كان غير ضروري
- لا حذف أي وظيفة موجودة
- لا تغيير نظام الاشتراكات العام
- لا تغيير نظام الشحن الأساسي
- لا عمل Refactoring شامل
- الهدف: إنشاء الهيكل الكامل والصحيح للقسم مع الصفحات والأزرار والـ Actions جاهزة للربط الفعلي في PHASE 2
- بعد التنفيذ يجب اختبار التنقل بين جميع الأقسام والتأكد من عدم وجود Redirect أو Blank Screen أو Loading لا نهائي

### 4.14 منطق Offline-First
- تخزين البيانات الثابتة محلياً باستخدام Capacitor Preferences: إعدادات التطبيق، الكروت، الصور، الأيقونات
- فتح التطبيق من التخزين المحلي أولاً
- مزامنة ذكية في الخلفية
- لا skeleton طويل، لا صور مكسورة، لا تحميل بطيء

### 4.15 منطق منع التكرار
- Request Deduplication: نفس الطلب لا يُرسل مرتين
- Notification Deduplication: نفس الإشعار لا يظهر مرتين
- Toast Deduplication: نفس الرسالة لا تظهر مرتين
- Order Deduplication: نفس العملية لا تُنفَّذ مرتين

### 4.16 منطق Network Manager
- مراقبة الاتصال وجودة الشبكة
- كشف Offline واستعادة تلقائية
- إعادة مزامنة عند عودة الإنترنت
- تحسين جميع الطلبات للعمل بأقل سرعة ممكنة

### 4.17 منطق حذف المستخدم نهائياً
- حذف من: Auth، Database، Profiles، Sessions، Notifications، Activity، Logs
- إذا كان المستخدم داخل التطبيق: عرض رسالة تم حذف حسابك بواسطة الإدارة. ثم تسجيل خروج فوري

### 4.18 منطق نظام الحظر
- المحظور لا يستطيع تسجيل دخول ولا إنشاء Session
- عرض رسالة: تم حظر حسابك بواسطة الإدارة.

### 4.19 منطق نظام الإشعارات
- فحص مكان التخزين (Supabase/Local)
- نظام تنظيف تلقائي: حذف إشعارات أقدم من 30 يوماً للمستخدمين
- منع تكرار الإشعارات
- كل مستخدم جديد يبدأ بإشعاراته الخاصة فقط

### 4.20 منطق أزرار النسخ
- زر Copy بجانب: اسم المستخدم، User ID، رقم الهاتف، البريد، رقم العملية، Transaction ID
- عند الضغط: نسخ النص إلى الحافظة

### 4.21 منطق إعادة بناء لوحة الإدارة
- حذف جميع Popup/Modal/Dialog المتعلقة بإدارة المستخدمين
- استبدالها بصفحات كاملة (Full Screen Pages)
- كل صفحة تحتوي على: Header واضح، Breadcrumb، محتوى منظم، Sticky Action Bar
- Animations احترافية عند التنقل بين الصفحات
- Loading States و Skeleton Loading
- Confirmation Dialogs للإجراءات الحساسة
- Success/Error Messages واضحة
- الحفاظ على الهوية البصرية الحالية والثيم
- لا تغيير على أي منطق موجود (API، قاعدة البيانات، المصادقة، Edge Functions)
- الحفاظ على جميع الوظائف الحالية وعدم كسر أي جزء

### 4.22 منطق Application Version Center
- تخزين معلومات الإصدارات في قاعدة البيانات
- تحديث معلومات الإصدار عند إصدار نسخة جديدة
- مقارنة إصدار المستخدم مع آخر إصدار متاح
- إجبار المستخدم على التحديث إذا كان Force Update مفعلاً
- منع المستخدم من الدخول إذا كان إصداره محظوراً
- منع المستخدم من الدخول إذا كان إصداره أقل من الحد الأدنى

### 4.23 منطق Live Monitoring
- تسجيل كل اتصال للمستخدم
- تحديث حالة المستخدم (Online/Offline) تلقائياً
- تسجيل آخر نشاط لكل مستخدم
- تسجيل الإصدار المستخدم
- تسجيل الجهاز المستخدم
- تسجيل آخر API Request
- تسجيل آخر Runtime Config
- تسجيل آخر Feature Flags
- تحديث البيانات كل 10 ثوانٍ

### 4.24 منطق Feature Management
- تخزين حالة كل ميزة في قاعدة البيانات
- تحميل حالة الميزات عند فتح التطبيق
- تحديث حالة الميزات من الخادم كل 30 ثانية
- إخفاء الميزة المعطلة من واجهة المستخدم
- منع تنفيذ الميزة المعطلة
- تطبيق التغيير فوراً على جميع المستخدمين المتصلين
- تسجيل كل تعديل في سجل النظام

### 4.25 منطق تحسين تجربة الاستخدام
- Animations ناعمة عند التنقل بين الصفحات
- Loading States واضحة

- Error Messages واضحة عند فشل الإجراء
- Search أسرع مع Debounce
- Pagination لتحسين الأداء
- Filters متعددة

- Sticky Header عند التمرير
- Sticky Action Bar عند التمرير
- Responsive Design لجميع الأجهزة
- Mobile First

### 4.26 منطق تقييم الكروت واقتراح التعديلات

#### 4.26.1 عرض زر التقييم
- يظهر زر تقييم الكارت / اقتراح تعديل في موضعين:
  - بعد نجاح عملية الشحن مباشرة
  - بجانب كل عملية ناجحة في سجل العمليات
- الزر يظهر فقط إذا كانت ميزة تقييم الكروت مفعلة في Feature Management
- إذا تم إيقاف الميزة: يختفي الزر فوراً من جميع المستخدمين

#### 4.26.2 نافذة التقييم
- عند الضغط على زر التقييم: فتح نافذة منبثقة (Popup)
- عرض معلومات العملية: رقم العملية، نوع الكارت، التاريخ
- حقول الإدخال:
  - عدد الوحدات الفعلية (حقل رقمي، اختياري)
  - السعر المخصوم الفعلي من فودافون كاش (حقل رقمي، اختياري)
  - أيام الصلاحية الفعلية (حقل رقمي، اختياري)
- زر رفع سكرين شوت:
  - اختياري
  - يسمح برفع صورة واحدة فقط
  - الصيغ المدعومة: PNG, JPG, JPEG
  - الحد الأقصى لحجم الملف: 5 MB
  - عرض الصورة بشكل مصغر بعد الرفع
  - إمكانية حذف الصورة قبل الإرسال
- زر إرسال التقييم
- زر إلغاء

#### 4.26.3 إرسال التقييم
- التحقق من صحة البيانات المدخلة
- رفع السكرين شوت إلى Supabase Storage (إن وجد)
- حفظ التقييم في قاعدة البيانات مع:
  - User ID
  - اسم المستخدم
  - رقم العملية
  - نوع الكارت
  - تاريخ العملية
  - تاريخ التقييم
  - البيانات المقترحة (الوحدات، السعر، الصلاحية)
  - رابط السكرين شوت (إن وجد)
  - حالة التقييم: جديد
- عرض رسالة نجاح
- إغلاق النافذة

#### 4.26.4 إدارة التقييمات (Admin)
- عرض جميع التقييمات في صفحة Card Feedback
- فلترة وترتيب التقييمات
- عرض تفاصيل كل تقييم
- عرض السكرين شوت بحجم كامل عند الضغط عليه
- تغيير حالة التقييم: جديد، قيد المراجعة، تم التطبيق، مرفوض
- إضافة ملاحظات Admin على التقييم
- حذف تقييم
- تصدير التقييمات

#### 4.26.5 Feature Flag
- إضافة مفتاح تحكم في Feature Management: ميزة تقييم الكروت
- عند تفعيل الميزة: يظهر زر التقييم لجميع المستخدمين
- عند إيقاف الميزة: يختفي زر التقييم فوراً من جميع المستخدمين
- التطبيق فوري بدون الحاجة لإعادة تحميل الصفحة

### 4.27 منطق الأمان وحماية البيانات
- عدم تخزين passwords في logs أو frontend
- عدم تخزين OTP في logs أو frontend
- عدم تخزين tokens في logs أو frontend
- جميع البيانات الحساسة يتم تشفيرها
- جميع الطلبات تستخدم HTTPS
- جميع الصلاحيات يتم التحقق منها Server-Side
