## 2. المستخدمون وسيناريوهات الاستخدام

### 2.1 المستخدمون المستهدفون
- المالك العام (Owner - nader77@miaoda.com): التحكم الشامل في المنظومة، تفويض صلاحيات قسم VIP للمستخدمين وتعيين حدودهم، مراقبة وفحص الجلسات، كشف محاولات التلاعب وإدارة الحظر، ومتابعة تحديثات النظام وبناء الحزم عبر GitHub Actions.
- المستخدم المصرح له بقسم VIP (Delegated VIP User): مستخدم معتمد من قبل المالك يمتلك واجهة تنفيذية مبسطة لتشغيل الجلسات وإجراء التحويلات ضمن الحدود والفواصل الزمنية المفروضة خادمياً.
- مستخدمو النظام العاديون والعملاء: متابعة خدمات فودافون ريد بيزنس دون إمكانية رؤية أو الوصول إلى قسم VIP.

### 2.2 السيناريوهات الأساسية
- منح وتخصيص صلاحيات VIP: يقوم المالك بتفعيل الوصول لمستخدم محدد وتعيين الحد الأقصى للدورات (Cycle Limit) والفاصل الزمني الإجباري بين الدورات (Cooldown Delay).
- تشغيل الجلسات من واجهة العميل: يقوم المستخدم المصرح له بتنفيذ عمليات التحويل ضمن حدوده المحددة، مع عرض ملخص النتائج النهائي ورصيد الميكسات فقط وحجب أي تفاصيل برمجية.
- التدخل الأمني الخادمي والحظر الفوري: عند رصد أي محاولة تعديل محلية أو طلب غير مصرح به أو محاولة تجاوز الفاصل الزمني، يقوم السيرفر بإنهاء الجلسة وحظر الحساب والجهاز فوراً.
- الفحص والمراقبة من لوحة المالك: فحص سجلات الجلسات النشطة، تتبع العمليات الناجحة والفاشلة، تعديل الحدود التشغيلية أو سحب التفويض بضغطة زر.
- إدارة التحديثات وبناء التطبيق: متابعة سير عمل GitHub Actions وسجلات git tags لإطلاق الإصدارات وإشعار المستخدمين.

## 3. هيكل الصفحات والوظائف

### 3.1 هيكل الصفحات

```
Vodafone Fakka Premium
├── صفحة تسجيل الدخول والمصادقة الأمنية
├── لوحة تحكم المالك (Admin / Owner Panel)
│   ├── إدارة تفويض وصلاحيات قسم اتصالات VIP
│   │   ├── قائمة المستخدمين وتعيين الحدود (الدورات والفاصل الزمني)
│   │   └── مركز مراقبة وفحص الجلسات وتشخيص الأخطاء (Session Inspector)
│   ├── سجل الأمان وكشف التلاعب وإدارة الحظر (Anti-Tamper & Ban Log)
│   ├── قسم فودافون ريد بيزنس VIP
│   ├── قسم إدارة WhatsApp Business
│   └── إدارة إصدارات وتحديثات النظام (GitHub Actions & Releases)
├── واجهة المستخدم المصرح له بقسم اتصالات VIP (المسار: /vip)
│   ├── مؤشر الرصيد وحالة الحصة المتبقية من الدورات
│   ├── واجهة تشغيل الجلسة المقتضبة (عرض النتائج النهائية فقط)
│   └── مؤشر الفاصل الزمني الإجباري (Cooldown Timer)
└── بوابة خدمات فودافون والعملاء العامة
```

### 3.2 بنية الأمان الخادمي ونظام كشف التلاعب (Zero-Trust Security & Anti-Tamper)
- معالجة خادمية حصرية: تنفيذ كافة المنطق البرمجي، التحقق من الجلسات، وعمليات الاتصال بالشبكة من خلال السيرفر وقواعد الأمان الخلفية بشكل كامل، دون الاعتماد على أي منطق من جهة العميل.
- كشف التلاعب والحظر التلقائي: رصد الاستدعاءات المشبوهة، محاولات التلاعب بالصلاحيات أو تكرار الطلبات غير القانوني، وحظر المستخدم والجهاز وإبطال الجلسة خادمياً بصورة فورية.
- عزل الصلاحيات: حجب قسم اتصالات VIP تماماً عن كافة المستخدمين غير المصرح لهم بحيث يتعذر الوصول إليه عبر المسارات المباشرة أو واجهات برمجة التطبيقات.

### 3.3 نظام تفويض وتخصيص قسم اتصالات VIP
- إدارة التفويض: لوحة للمالك لإضافة وإلغاء تفعيل صلاحية الوصول لقسم VIP لمستخدمين محددين (عبر المعرف أو البريد الإلكتروني).
- إدارة الحدود التشغيلية (Quotas & Limits):
  - تحديد الحد الأقصى للدورات والميكسات المسموح بها لكل مستخدم.
  - فرض فاصل زمني إجباري خادمي (Cooldown) بين كل دورة تشغيلية وأخرى (مثل 20 ثانية أو 60 ثانية) مع قفله برمجياً على مستوى السيرفر.
  - حصر تعديل هذه القيم بالمالك فقط.

### 3.4 واجهة العميل المبسطة (Client-Facing UI)
- واجهة تنفيذية نظيفة ومقفلة أمنياً تقتصر على عرض:
  - رسالة نتيجة العملية النهائية («تم التحويل للفرد» و«تم التحويل للأونر»).
  - رصيد الميكسات وحالة الحصة المتبقية.
  - عداد تنازلي للفاصل الزمني المفروض خادمياً قبل السماح بالعملية التالية.
- حجب سجلات التنفيذ الفنية، مسارات الاستدعاء، والبيانات الحساسة عن واجهة العميل، مع منع استخراج أو استنساخ الطلبات.

### 3.5 لوحة المالك وفاحص الجلسات (Owner Inspector & VIP Management)
- استعراض شامل لكافة المستخدمين المصرح لهم وحالة نشاطهم.
- تفاصيل تفاعلات كل جلسة: عدد الدورات الناجحة والفاشلة، معدل الاستهلاك، وتاريخ آخر نشاط.
- شاشة تشخيص متقدمة لعرض الأخطاء والأسباب الفنية للتعثر.
- أزرار تحكم سريعة لتعديل الحصص أو تجميد الصلاحية أو إيقاف الجلسة فورياً.

### 3.6 إدارة الإصدارات وبناء التطبيق
- متابعة تدفقات GitHub Actions لبناء الحزم ومطابقة وسوم الإصدارات (Git Tags).
- توثيق سجل الإصدارات وتحديث رقم الإصدار في النظام وإرسال إشعارات التحديث للمستخدمين.

## 4. قواعد العمل والمنطق الأساسي

### 4.1 قواعد الأمان والتفويض
1. لا يمكن لأي مستخدم الوصول إلى قسم اتصالات VIP ما لم يكن حسابه مفعلاً وموثقاً في جدول الصلاحيات الخادمي من قبل المالك.
2. يتم التحقق من صحة الفاصل الزمني الإجباري (Cooldown) على مستوى السيرفر قبل معالجة أي دورة جديدة، ويتم رفض أي طلب وارد قبل انقضاء المهلة المحددة خادمياً.
3. عند تجاوز المستخدم للحد الأقصى المخصص له من الدورات، يتم إيقاف تنفيذ العمليات آلياً وإشعار المستخدم بضرورة الرجوع للمالك لزيادة الحصة.
4. تؤدي أي محاولة تلاعب بالبارامترات أو استدعاء مباشر لوظائف النظام المحمية إلى تنفيذ إجراء الحظر الفوري للجهاز والحساب على مستوى السيرفر.

### 4.2 قواعد تسلسل الإخراج والتحويل
5. يخضع تسلسل إخراج الفرد للتنفيذ الخادمي الكامل بدءاً بتجديد باقة الأونر، تليها محاولات الإخراج وفحص الحالة، ثم فترة الانتظار المقررة في حال التعليق.
6. يتم تحويل خط الفرد تلقائياً إلى نظام 270 عند تأكيد الخروج الخادمي، مع توفير خيار التحويل إلى نظام أهلاً أقوى كارت (MINION) يدوياً فقط عند تعليق الخروج.

## 5. الحالات الاستثنائية والحدود

| الحالة | السلوك المتوقع |
|---|---|
| محاولة وصول مستخدم غير مفوض إلى مسار VIP | إعادة توجيهه إلى الصفحة الرئيسية مع تسجيل محاولة وصول غير مصرح بها |
| إرسال طلب تشغيل دورة قبل انتهاء فترة الـ Cooldown | رفض الطلب خادمياً وإرجاع الوقت المتبقي لانتهاء الفاصل الزمني |
| رصد تلاعب برمجي بالطلبات أو محاولة كسر الصلاحيات | حظر الحساب والجهاز فوراً من السيرفر وإلغاء الجلسات وتسجيل الحادثة في سجل الأمان |
| استنفاد المستخدم للحد الأقصى المسموح به من الدورات | تعطيل زر بدء الدورة في واجهة العميل وإظهار تنبيه بانتهاء الحصة المخصصة |
| تعليق خروج الفرد من العائلة بعد استنفاد محاولات الإخراج | إيقاف المحاولات التلقائية وتوفير خيار التحويل اليدوي إلى نظام MINION لفك التعليق |

## 6. معايير القبول

1. حجب قسم اتصالات VIP تماماً عن المستخدمين غير المعتمدين واقتصار الوصول على المالك والمستخدمين المفوضين منه.
2. إمكانية قيام المالك بتحديد وتعديل حد الدورات والفاصل الزمني الإجباري (Cooldown) لكل مستخدم مفوض مع فرضه خادمياً.
3. قفل واجهة العميل المفوض بحيث تعرض فقط نتائج العمليات النهائية ورصيد الميكسات، وحجب كافة السجلات التقنية والتفاصيل البرمجية الحساسة.
4. توفير لوحة تشخيص ومراقبة متكاملة للمالك (Session Inspector) تعرض تفاصيل الجلسات والعمليات والأخطاء مع إمكانية إلغاء الصلاحية فورياً.
5. تنفيذ الحظر الخادمي الفوري للحساب والجهاز عند رصد أي محاولة تلاعب أو استدعاءات غير مصرح بها.
6. الحفاظ على تسلسل الإخراج الذكي المنقح وخيارات تحويل الأنظمة المعتمدة مع توثيق الإصدارات والتكامل مع مسارات البناء.
