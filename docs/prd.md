## 2. المستخدمون وسيناريوهات الاستخدام

### 2.1 المستخدمون المستهدفون
- مسؤولو النظام (Admin): مراجعة واعتماد طلبات ربط الأرقام، إدارة التجار، متابعة الفواتير وحالات السداد، التحكم في إعدادات ودورة الفحص التلقائي (بالدقائق أو الساعات) وضبط خيارات الإدارة والتنبيهات، ومراقبة سجلات الفحص وتلقي كلمات المرور الجديدة.
- التجار والمستخدمون المسجلون: استكمال الملف التعريفي، البحث عن الأرقام غير المعينة وطلب ربطها بالحساب، متابعة الأرقام المعتمدة مع عرض نظام الخط (14 قرش / ريد)، إمكانية الفحص اليدوي المباشر، إرسال كلمة سر أنا فودافون بعد التحويل، ومتابعة الفواتير.

### 2.2 السيناريوهات الأساسية
- تسجيل المستخدم لبيانات الملف التعريفي عند أول دخول.
- بحث المستخدم عن الأرقام وإرسال طلب اعتماد لربطها بحسابه.
- اعتماد أو رفض الطلبات من قبل الإدارة مع بيان السبب.
- ضبط وتعديل إعدادات دورة الفحص الدوري وخيارات الإدارة وتطبيق التغييرات فورياً على الأرقام وحساب مواعيد الفحص القادمة.
- استعراض بطاقات الأرقام بحجم مضغوط مع وسم نظام الخط الحالي (14 قرش للأرقام غير المحولة / ريد للأرقام المحولة).
- تنفيذ الخادم لعمليات الفحص الدوري في الخلفية وفق الإعدادات والجدولة المحدثة.
- إرسال تنبيه للمستخدم فور تحويل الخط لنظام ريد لإدخال كلمة السر الجديدة للإدارة.
- احتساب الفواتير الشهرية تلقائياً وفق الباقات ودورات التجديد.

### 3.2 شاشة التسجيل والملف التعريفي
- إلزام المستخدم الجديد بإدخال الاسم واللقب ورقم الواتساب عند أول دخول.
- ربط الملف التعريفي بمعرف المستخدم وحفظه في قاعدة البيانات.

### 3.3 بوابة التاجر/المستخدم المستقلة
- البحث عن الأرقام غير المعينة وتقديم طلب الربط ومتابعة حالة الطلب.
- عرض الأرقام المعتمدة مصنفة حسب دورة التجديد (7، 11، 25).
- بطاقات الأرقام المضغوطة وتتضمن:
  * رقم الهاتف، نوع باقة ريد، قيمة الفاتورة، تاريخ التجديد القادم.
  * وسم نظام الخط باختصار ووضوح: عرض «14 قرش» (أو النظام الفعلي) للخطوط قبل التحويل، وعرض «ريد» للخطوط بعد التحويل، دون زيادة أبعاد البطاقة.
  * وقت آخر فحص، وزر الفحص اليدوي المباشر.
  * حجب صلاحيات الحذف أو التعديل الهيكلي عن المستخدم العادي.
- نافذة إدخال كلمة سر أنا فودافون الجديدة فور تحويل الخط.

### 3.4 لوحة تحكم وإعدادات قسم ريد (خاص بالمسؤول)
- التحكم المرن في دورة الفحص الزمني:
  * حقل مخصص لإدخال مدة دورة الفحص وتحديد الوحدة (دقائق أو ساعات) بحرية تامة دون التقيد بقيم مسبقة.
  * حفظ التغييرات وتطبيقها فعلياً وفورياً على جميع الأرقام ومجدول الخادم، وإعادة احتساب موعد الفحص القادم لكل رقم بناءً على الإعدادات الجديدة.
- خيارات التحكم والإدارة الموسعة:
  * مفتاح تفعيل/تعطيل الفحص التلقائي بالخلفية بشكل كامل.
  * ضبط الحد الأقصى لعدد محاولات إعادة الفحص عند التعثر.
  * إعدادات التنبيهات وتحديد أحداث الإشعار المطلوبة.
  * خيارات تخصيص العرض والفرز للأرقام.
- سجل الفحص ومراقبة استجابة الخادم وحالة معالجة الدفعات.

### 3.5 نظام الفحص الدوري التلقائي في الخلفية (Server-side Scheduler)
- تشغيل الفحص على مستوى الخادم بانتظام ودون اشتراط فتح المتصفح وفق المدة المحددة في الإعدادات.
- فحص الأرقام بنظام الدفعات المقسمة والمجدولة زمنياً لحماية العمليات وتفادي الضغط.
- تحديث حالات الأرقام ووقت الفحص في قاعدة البيانات تلقائياً وتوليد الإشعارات عند التغيير.

### 3.6 مراجعة الطلبات، إدارة التجار، وإدارة التجديدات
- مراجعة طلبات الربط مع إلزامية كتابة سبب الرفض.
- إدارة بيانات التجار وحساباتهم.
- استعراض فواتير باقات ريد (450 ج / 550 ج / 700 ج) وتأكيد السداد وتعديل اسم العميل.

## 4. قواعد العمل والمنطق الأساسي

1. فاعلية حفظ الإعدادات والتطبيق الفوري:
   - عند حفظ إعدادات دورة الفحص أو خيارات الإدارة، يتم تحديث القيم في قاعدة البيانات فوراً، وتحديث معايير مجدول الخادم، وإعادة احتساب الموعد القادم للفحص لجميع الأرقام المشمولة دون الحاجة لإعادة تشغيل النظام.
2. مرونة ضبط دورة الفحص:
   - يقبل النظام إدخال الفترات الزمنية بالدقائق أو بالساعات كأرقام صحيحة موجبة، وتُترجم برمجياً إلى الجدولة المقابلة بدقة.
3. تمييز نظام الخط في البطاقات:
   - يتم تحديد نص النظام المعروض داخل بطاقة الرقم تلقائياً؛ فإذا لم يتم اعتماد تحويل الخط إلى ريد بعد يظهر «14 قرش» (أو اسم نظامه الفعلي)، وفور التحويل المعتمد يتحول الوسم إلى «ريد» مع الحفاظ على التصميم المدمج.
4. استقلالية الفحص ومعالجة الدفعات:
   - يعمل الفحص التلقائي على الخادم باستمرار ويقسم العمليات إلى دفعات محددة بفواصل زمنية آمنة.
5. صلاحيات الأرقام والبيانات السرية:
   - لا تُعرض الأرقام إلا بعد اعتماد الإدارة، وتتاح كلمة السر الجديدة للمسؤول حصراً بعد إرسالها من المستخدم.
6. دورة الفواتير والإشعارات:
   - إرسال التنبيهات للمستخدمين والإدارة عند تغير حالة الخط، أو اقتراب موعد التجديد، أو تحديث حالة الطلبات.

## 5. الحالات الاستثنائية والحدود

| الحالة | السلوك المتوقع |
|---|---|
| حفظ قيمة غير صالحة أو سالبة لمدة دورة الفحص | رفض الحفظ وإظهار تنبيه يوضح ضرورة إدخال رقم موجب بالدقائق أو الساعات |
| تعديل مدة الفحص أثناء تشغيل دورة فحص حالية | إكمال الدفعة الحالية ثم تطبيق الجدولة الجديدة على الدورات القادمة وإعادة ضبط موعد الفحص القادم للأرقام |
| تعطيل الفحص التلقائي من لوحة التحكم | إيقاف المجدول فورياً مع إبقاء إمكانية الفحص اليدوي المباشر للأرقام |
| إغلاق المتصفح أو خروج المسؤول والمستخدمين | استمرار تنفيذ الجدولة التلقائية وحفظ السجلات على الخادم وفق الإعدادات المحفوظة |
| محاولة استخدام النظام قبل ملء الملف التعريفي | توجيه المستخدم لإدخال الاسم واللقب ورقم الواتساب أولاً |
| رفض طلب ربط رقم بدون كتابة السبب | منع إتمام الإجراء وإلزام المسؤول بتسجيل سبب الرفض |

## 6. معايير القبول

1. نجاح حفظ وتطبيق تعديلات إعدادات الفحص وخيارات التحكم من لوحة الإدارة وانعكاسها الفوري على جدولة المجدول ومواعيد الفحص القادمة للأرقام.
2. إتاحة تخصيص مدة دورة الفحص بحرية (سواء بالدقائق أو الساعات) وقبول القيم المدخلة بصورة صحيحة.
3. عمل مفاتيح التحكم الإضافية (تفعيل/تعطيل الفحص التلقائي، عدد المحاولات، تنبيهات النظام) بشكل سليم وفعال.
4. ظهور وسم نظام الخط بوضوح واختصار في بطاقة الرقم («14 قرش» للخطوط غير المحولة و«ريد» للمحولة) دون التأثير على الحجم المضغوط للبطاقة.
5. استمرار تشغيل مجدول الفحص في الخلفية على مستوى الخادم بنظام الدفعات الآمنة دون اشتراط فتح المتصفح.
6. تمكن المستخدم الجديد من استكمال بياناته والبحث عن الأرقام وطلب اعتمادها، وتمكن الإدارة من قبولها أو رفضها مع سبب الرفض.
7. إتاحة حقل إرسال كلمة سر أنا فودافون الجديدة وحفظها للإدارة فور تحويل الخط.
8. دقة احتساب الفواتير الشهرية وعرض ملخص الاستحقاقات حسب دورات التجديد (7، 11، 25).

- إرسال الرسائل النصية المباشرة (SMS) عبر شبكات الاتصالات خارج إشعارات المنصة.
