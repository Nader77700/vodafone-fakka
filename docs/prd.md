### 1.1 اسم التطبيق
Vodafone Fakka Premium (نظام إدارة وباقات فودافون ريد بيزنس VIP، قسم أتمتة اتصالات VIP، وإدارة إشعارات واتساب)

### 1.2 المالك والمطور
Nader Akram

### 1.3 الوصف
منصة ويب تجمع بين إدارة خطوط فودافون ريد بيزنس ونظام إشعارات WhatsApp Business، بالإضافة إلى قسم مخصص ومحمي بالخادم لأتمتة باقات اتصالات حكاية عيلة عبر محرك EtisalatBot المعتمد على واجهات Etisalat MAB API. يتيح قسم اتصالات VIP للمالك المصرح له إدارة جلسات متعددة ومستقلة، وعرض بيانات الأونر والفرد بدقة، وإدارة ربط أفراد العائلة (إرسال وقبول الدعوات آلياً)، وتنفيذ العمليات اليدوية الفردية، وتشغيل الدورات التلقائية لتجديد الباقات وتحويل الميكسات والترحيل بين الأنظمة مع سجلات حية مطابقة لمخرجات السكريبت المرجعي.

## 2. المستخدمون وسيناريوهات الاستخدام

### 2.1 المستخدمون المستهدفون
- المالك المصرح له (Authorized Owner): الوصول الحصري لقسم اتصالات VIP، إنشاء وإدارة الجلسات المتعددة، تنفيذ الإجراءات الفردية، وتشغيل وإيقاف الأتمتة التلقائية.
- مسؤولو النظام (Admin): إدارة ومراجعة طلبات باقات فودافون ريد بيزنس، ومتابعة الفواتير وإشعارات WhatsApp Business.
- التجار والعملاء: متابعة الخطوط المعتمدة وتواريخ الفواتير والتجديدات التابعة لفودافون.

### 2.2 السيناريوهات الأساسية
- التحقق من صلاحيات المالك على مستوى الخادم قبل السماح بالدخول إلى مسار `/vip` أو تنفيذ أي عملية عبر الخادم.
- إنشاء جلسة جديدة عبر إدخال: اسم الجلسة، بريد وكلمة مرور الأونر، بريد وكلمة مرور الفرد، تحديد رصيد الميكسات المستهدف، وتحديد زمن الانتظار بين الدورات.
- فحص حالة الجلسة واستخراج أرقام الخطوط، استهلاك الأونر، قائمة أفراد العائلة (fafNumberList)، وحالة ربط الفرد.
- إضافة فرد جديد إلى العائلة آلياً (إرسال الدعوة من حساب الأونر وقبولها وتأكيدها عبر حساب الفرد بنقرة واحدة).
- تنفيذ إجراءات تشغيلية يدوية فردية (تجديد الباقة، تحويل الميكسات، ترحيل النظام، استرجاع ميكسات الفرد للأونر).
- تشغيل الدورة التلقائية (Auto Loop) المستمرة مع متابعة شريط التقدم نحو الهدف، عداد الثواني بين الدورات، ومراقبة شاشة السجلات الحية (Terminal Logs).

### 3.2 إدارة جلسات اتصالات VIP (Multi-Session Management)
- شريط اختيار الجلسات: استعراض الجلسات المحفوظة، التبديل الفوري بينها، إظهار معرّف الجلسة، اسمها، حالتها التشغيلية، ورقم الدورة الحالية.
- نافذة إنشاء جلسة جديدة: تشتمل حصراً على الحقول التالية:
  - اسم الجلسة (اختياري).
  - البريد الإلكتروني لحساب الأونر (إلزامي).
  - كلمة مرور حساب الأونر (إلزامي).
  - البريد الإلكتروني لحساب الفرد (إلزامي).
  - كلمة مرور حساب الفرد (إلزامي).
  - تحديد هدف الميكسات: خيارات محددة (50,000 / 100,000 / 150,000 / 200,000) أو إدخال رقم صحيح موجب يدوياً.
  - مدة الانتظار بين الدورات بالثواني (افتراضياً 20 ثانية، مع قبول 0 أو أي رقم صحيح موجب).
- عزل بيانات الاعتماد ورموز المصادقة وسياق التنفيذ لكل جلسة بشكل مستقل وتام.

### 3.3 بطاقات تفاصيل الجلسة النشطة
- بطاقة بيانات الأونر (Owner Overview Card):
  - عرض البريد الإلكتروني للأونر.
  - عرض رقم الخط المستخرج تلقائياً بعد أول تسجيل دخول.
  - عرض النظام الحالي للأونر: Hekaya_XRP_MIX_Parent_7 (270 جنيهاً) أو Hekaya_XRP_MIX_Parent_6 (180 جنيهاً).
  - عرض رصيد الميكسات الحالي للأونر وإجمالي الاستهلاك.
- بطاقة بيانات وحالة الفرد (Child Status & Family Card):
  - عرض البريد الإلكتروني للفرد.
  - عرض رقم خط الفرد المكتشف من قائمة العائلة (fafNumberList).
  - عرض رصيد الميكسات الحالي لدى الفرد.
  - مؤشر حالة الربط: بيان واضح يوضح هل يوجد فرد مربوط بالعيلة أم لا.
  - قسم ربط فرد جديد: حقل إدخال رقم الفرد، زر إرسال الدعوة من الأونر وقبولها وتأكيدها آلياً عبر حساب الفرد (تنفيذ add_child ثم confirm_add_child وفق السكريبت).
- بطاقة فحص وتغيير النظام (Plan Migration Card):
  - استعراض النظام الحالي وقيمة التجديد المقابلة.
  - تحديد وخيارات الترحيل المباشر بين نظام 270 (Parent 7) ونظام 180 (Parent 6).
  - زر فحص النظام الحالي وتحديث بيانات الباقة من الخادم.

### 3.4 لوحة التحكم والإجراءات المباشرة
- لوحة التحكم الفردي اليدوي (Manual Action Triggers):
  - زر فحص الحالة الشاملة وتحديث الأرصدة (Check Status).
  - زر تجديد باقة الأونر الحالية (Renew Package).
  - زر تحويل كامل الميكسات المتاحة من الأونر إلى الفرد (Transfer Mixes to Child).
  - زر تغيير وترحيل النظام إلى النظام المقابل (Migrate Plan).
  - زر تسجيل دخول الفرد واسترجاع الميكسات المتاحة إلى الأونر (Return Mixes from Child).
- لوحة التشغيل التلقائي للدورات (Auto Loop Control Panel):
  - أزرار التحكم بالدورة: بدء التشغيل الفعلي (Start Loop)، إيقاف مؤقت (Pause)، استئناف (Resume)، وإيقاف طارئ (Emergency Stop).
  - إعدادات الهدف: تعديل الرصيد المستهدف أثناء التشغيل واختيار القيم المحددة مسبقاً أو القيمة المخصصة.
  - إعدادات التوقيت: تعديل زمن الانتظار بين الدورات بالثواني.
  - مؤشرات التقدم: شريط تقدم بصري يوضح نسبة الإنجاز نحو هدف الميكسات، عداد تنازلي لثواني الانتظار بين الدورات، ورقم الدورة الحالية.

### 3.5 شاشة السجلات الحية (Live Terminal Logs)
- نافذة سجلات طرفية متزامنة مع الخادم تعرض المخرجات النصية التشغيلية للسكريبت خطوة بخطوة.
- توثيق تفاصيل الخطوات: تسجيل الدخول، استخراج التوكن، استعلام الاستهلاك، تجديد الباقة مع فترات الانتظار، استجابات التحويل، وحلقات استعلام تغيير النظام كل ثانيتين.
- حظر تسجيل أو عرض كلمات المرور أو التواقيع المشفرة الحساسة داخل السجلات.

### 3.6 أقسام فودافون ريد وإشعارات واتساب
- استمرار عمل قسم فودافون ريد بيزنس VIP وقسم إشعارات WhatsApp بكامل وظائفهما السابقة دون أي تعديل أو تأثر.

## 4. قواعد العمل والمنطق الأساسي

1. المرجعية التشغيلية: تنفيذ جميع عمليات اتصالات عبر دوال الخادم المتصلة حصراً بواجهات Etisalat MAB API وفق منطق السكريبت المرجعي.
2. تسلسل الدورة التلقائية (Auto Loop Lifecycle):
   - الخطوة 1: تسجيل دخول الأونر بالبريد وكلمة المرور، استخراج رمز المصادقة ورقم الخط.
   - الخطوة 2: فحص استهلاك الأونر والتحقق من وجود فرد مربوط. في حال عدم وجوده، تتوقف الدورة مع تنبيه بضرورة الربط.
   - الخطوة 3: التحقق من بلوغ الرصيد المستهدف؛ في حال تحققه، تتوقف الجلسة وتُعلّم كمكتملة.
   - الخطوة 4: تجديد باقة الأونر (270 ج.م لنظام Parent 7 أو 180 ج.م لنظام Parent 6):
     - عند النجاح: تطبيق تأخير 3 ثوانٍ قبل المتابعة.
     - عند الفشل: تطبيق تأخير 15 ثانية وتخطي باقي خطوات الدورة.
   - الخطوة 5: تحويل كامل ميكسات الأونر المتاحة إلى رقم الفرد المربوط.
   - الخطوة 6: طلب تغيير النظام (من 7 إلى 6 أو العكس).
   - الخطوة 7: مراقبة استجابة الخادم كل ثانيتين حصراً حتى تتضمن الاستجابة النظام المستهدف ورصيد ميكسات أكبر من صفر.
   - الخطوة 8: تسجيل دخول الفرد وتحويل كامل الميكسات المتوفرة لديه إلى الأونر.
   - الخطوة 9: إعادة تسجيل دخول الأونر، تحديث الرصيد النهائي، وزيادة عداد الدورات.
   - الخطوة 10: تطبيق فترة الانتظار المحددة للجلسة (افتراضياً 20 ثانية) قبل بدء الدورة التالية.
3. آلية ربط الفرد (Child Management):
   - إرسال طلب إضافة الفرد (add_child) من حساب الأونر.
   - تسجيل دخول حساب الفرد واستخراج رمز التأكيد وقبول الدعوة وتأكيد الإضافة (confirm_add_child) تلقائياً.
4. ثبات الفواصل الزمنية الفنية:
   - فاصل مراقبة ترحيل النظام: ثانيتان (غير قابل للتعديل).
   - تأخير ما بعد نجاح التجديد: 3 ثوانٍ.
   - تأخير ما بعد فشل التجديد: 15 ثانية.
   - فترة الانتظار بين الدورات: تطبق بعد اكتمال الدورة فقط وقابلة للتعديل لكل جلسة.
5. عزل الجلسات: تشغيل كل جلسة بسياق مستقل كلياً لمنع تداخل الجلسات المتزامنة.

## 5. الحالات الاستثنائية والحدود

| الحالة | السلوك المتوقع |
|---|---|
| عدم وجود فرد مربوط بالعائلة أثناء بدء الدورة | إيقاف الدورة التلقائية فوراً، تحديث مؤشر الربط إلى «غير مربوط»، وعرض تنبيه لاستخدام بطاقة إضافة الفرد |
| فشل عملية قبول دعوة الفرد الجديد | عرض رسالة خطأ توضح سبب الفشل في السجلات الحية مع إمكانية إعادة المحاولة يدوياً |
| فشل تجديد باقة الأونر | الانتظار 15 ثانية، تسجيل حالة الفشل في السجل الحي، وتخطي باقي الخطوات للمحاولة في الدورة التالية |
| فشل تحويل الميكسات من الأونر للفرد | توثيق الخطأ في السجل الحي، تخطي خطوة التحويل، ومتابعة تنفيذ ترحيل النظام |
| تأخر استجابة ترحيل النظام | استمرار حلقة المراقبة كل ثانيتين حتى ظهور النظام الجديد ورصيد ميكسات صالح |
| فشل تسجيل دخول حساب الفرد أو الأونر | إيقاف الدورة مؤقتاً، توثيق سبب الفشل في السجلات الحية دون كشف كلمة المرور |
| الوصول إلى رصيد الميكسات المستهدف أو تجاوزه | إيقاف الدورة التلقائية بنجاح، تحويل حالة الجلسة إلى «مكتملة»، وتحديث شريط التقدم إلى 100% |

## 6. معايير القبول

1. احتواء واجهة الجلسة النشطة على بطاقات منظمة ومستقلة لكل من: بيانات الأونر، بيانات وحالة الفرد، فحص وتغيير النظام، الإجراءات اليدوية، والتشغيل التلقائي.
2. نجاح تنفيذ عملية ربط الفرد الجديد عبر بطاقة الفرد بإرسال الدعوة وتأكيد قبولها آلياً عبر حساب الفرد بنقرة واحدة.
3. عمل جميع أزرار الإجراءات الفردية اليدوية (فحص الحالة، تجديد الباقة، تحويل الميكسات، ترحيل النظام، استرجاع الميكسات) واستجابتها بشكل مباشر ومعزول.
4. تنفيذ الدورة التلقائية للتسلسل الكامل المطابق لسكريبت EtisalatBot مع التقيد بالفواصل الفنية (مراقبة كل ثانيتين، وتأخير التجديد 3 ثوانٍ/15 ثانية).
5. عرض مخرجات العمليات خطوة بخطوة في شاشة السجلات الحية (Live Terminal Logs) بالتزامن مع تنفيذ الخادم.
6. تحديث شريط التقدم نحو الهدف وتطبيق عداد الثواني بين الدورات وتوقف الدورة آلياً عند بلوغ الهدف المحدد.
7. إمكانية إدارة جلسات متعددة متزامنة مع العزل التام لبيانات الاعتماد والأرصدة والسجلات بين الجلسات.
8. حجب وإخفاء كلمات المرور والرموز الأمنية المشفرة من السجلات والواجهات.
